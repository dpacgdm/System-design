### 1. Vector Distance Metrics & SIMD Acceleration

Vector search operates on dense floating-point arrays generated by ML embedding models (e.g., OpenAI `text-embedding-3-large` = 3072 dimensions, `bge-large-en` = 1024 dimensions).

#### Distance Metric Formulas

| Metric | Formula | Best Used For |
| :--- | :--- | :--- |
| **Euclidean Distance ($L_2$)** | $d(u,v) = \sqrt{\sum_{i=1}^D (u_i - v_i)^2}$ | Spatial geometric distance where magnitude matters. |
| **Cosine Similarity** | $\cos(\theta) = \frac{u \cdot v}{\|u\| \|v\|} = \frac{\sum u_i v_i}{\sqrt{\sum u_i^2} \sqrt{\sum v_i^2}}$ | Text semantic similarity (orientation over magnitude). |
| **Inner / Dot Product (IP)** | $\text{IP}(u,v) = \sum_{i=1}^D u_i v_i$ | Unit-normalized vectors ($\|u\|=\|v\|=1$) & recommendation classification. |

#### Hardware SIMD Vectorization (AVX-512 / ARM NEON)

Modern CPUs execute vector dot products in parallel using 512-bit SIMD registers (`_mm512_fmadd_ps`). A single AVX-512 Fused Multiply-Add instruction computes 16 32-bit floating point multiplications per CPU cycle:

$$\text{Cycles for 1536-dim Dot Product} = \frac{1536}{16} = 96 \text{ CPU Cycles}$$

### 2. HNSW (Hierarchical Navigable Small World) Index Architecture

HNSW is the state-of-the-art graph-based ANN index algorithm (used in Qdrant, Weaviate, Milvus, pgvector).

```
HNSW MULTI-LAYER GRAPH STRUCTURE:

Layer 2 (Top Layer - Sparse):    [ Node A ] ──────────────────────────► [ Node F ]
                                     │                                      │
                                  Down Pointer                           Down Pointer
                                     ▼                                      ▼
Layer 1 (Medium Density):        [ Node A ] ──────► [ Node C ] ─────────► [ Node F ]
                                     │                  │                   │
                                  Down Pointer       Down Pointer        Down Pointer
                                     ▼                  ▼                   ▼
Layer 0 (Bottom - All Vectors):  [ Node A ] ──► [ Node B ] ──► [ Node C ] ──► [ Node D ] ──► [ Node F ]
```

#### Graph Construction & Routing Mechanics

1. **Probabilistic Layer Allocation:** When inserting a vector, a random maximum layer is chosen using an exponential decay probability: $l = \lfloor -\ln(\text{uniform}(0,1)) \cdot m_L \rfloor$.
2. **Greedy Routing (Top to Bottom):** Search begins at the top layer (`Layer 2`). The algorithm greedily traverses edges toward the neighbor closest to the query vector until reaching a local minimum, then steps down to the next layer.
3. **Bottom Layer Expansion (`efSearch`):** On `Layer 0`, a priority queue of size `efSearch` keeps track of nearest candidates to maximize recall.

### 3. IVF-PQ (Inverted File with Product Quantization) Compression

While HNSW provides high QPS, its RAM footprint is large. **IVF-PQ** reduces vector memory by **95%** using vector quantization.

```
IVF-PQ ARCHITECTURE:

1. Inverted File (IVF) Clustering:
   Vectors are clustered into K centroids via k-means. Query searches only `nprobe` nearest centroids.

2. Product Quantization (PQ):
   A 1024-dim vector is split into M=8 sub-vectors of 128 dimensions each.

   Original Vector (1024 dims FP32 = 4096 Bytes):
   ┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
   │ Sub-vec1 │ Sub-vec2 │ Sub-vec3 │ Sub-vec4 │ Sub-vec5 │ Sub-vec6 │ Sub-vec7 │ Sub-vec8 │
   └────┬─────┴────┬─────┴────┬─────┴────┬─────┴────┬─────┴────┬─────┴────┬─────┴────┬─────┘
        ▼          ▼          ▼          ▼          ▼          ▼          ▼          ▼
   [Code 42]  [Code 109]  [Code 12]  [Code 255] [Code 88]  [Code 3]   [Code 14]  [Code 201]

   Compressed Code Representation = 8 Bytes Total! (512x Memory Compression)
```

#### Asymmetric Distance Computation (ADC) Math

During query time, the uncompressed query vector $Q$ is compared against compressed code vectors using **ADC**:
1. Precompute distance table between query sub-vectors and the 256 codebook centroid sub-vectors ($O(M \times 256)$ distance ops).
2. Compute distance to any quantized database vector by summing $M$ byte lookups from the precomputed table ($O(M)$ additions).

### Principal Stretch

### 4. Vector RAM Footprint Sizing & Tradeoff Matrix

#### Memory Calculation Formula for HNSW Index

$$\text{RAM Bytes} = N \times \left( D \times \text{Bytes Per Element} + M_{\text{max}} \times 8 \text{ Bytes (Pointers)} \right)$$

For $N = 100,000,000$ vectors ($D = 1536$, FP32, $M_{\text{max}} = 16$):

$$\text{Vector RAM} = 100 \times 10^6 \times (1536 \times 4) = 614.4 \text{ GB}$$

$$\text{HNSW Pointer Overhead} = 100 \times 10^6 \times (16 \times 8) = 12.8 \text{ GB}$$

$$\text{Total HNSW RAM} \approx 627.2 \text{ GB RAM}$$

With **Scalar Quantization (SQ8)** (compressing FP32 to INT8):

$$\text{SQ8 RAM} \approx 100 \times 10^6 \times (1536 \times 1 + 12.8) \approx 166.4 \text{ GB RAM (73.5% Savings)}$$

## Decision Framework

```
VECTOR INDEX SELECTION QUICK CHOOSER:

  Dataset < 1M vectors, Need max QPS & 99% recall?  → HNSW (FP32 / FP16)
  Dataset > 50M vectors, RAM budget constrained?    → HNSW + SQ8 or IVF-PQ
  High insertion rate / Dynamic updates & deletes?  → Flat Index + GPU Acceleration or Qdrant/Milvus
  Relational data + Vector hybrid search?           → pgvector (HNSW index mode)
```

## Production Failure Patterns

```
PATTERN 1: HNSW OOM DURING INDEX BUILD
  Symptom:   Node OOM-killed during batch ingestion of 10M vectors.
  Cause:     HNSW graph construction requires high temporary memory allocations for candidate priority queues per thread (`efConstruction`).
  Fix:       Build index in smaller batches; adjust `max_indexing_threads`; allocate 30% RAM buffer above static size.

PATTERN 2: RECALL DEGRADATION FROM SOFT DELETES
  Symptom:   Search accuracy drops from 95% to 70% after bulk deletion ops.
  Cause:     Tombstoned nodes remain in HNSW graph to prevent breaking routing paths, causing search traversals to hit dead-ends.
  Fix:       Trigger asynchronous full graph compaction / re-indexing (`vacuum` operation).
```
